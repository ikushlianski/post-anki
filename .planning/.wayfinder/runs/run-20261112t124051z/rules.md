r1. Prod bot and API serve /_healthz and web serves /login. Health checks poll up to 12 tries, 5 seconds apart. (source: docs/ci-cd/gcp-setup.md)
r2. Prod domain is postanki.ilya.online (PROD_WEB_PUBLIC_URL default https://postanki.ilya.online). Prod project is post-anki in region europe-west1. (source: docs/ci-cd/gcp-setup.md)
r3. The deploy pipeline does not register the Telegram webhook. It is a one-time manual `npm run set-webhook -w @post-anki/bot -- <url>/telegram`. A green health check does not mean a working bot, so the smoke test must verify the webhook config without setting it. (source: docs/ci-cd/gcp-setup.md)
r4. Telegram secrets are CI secrets PROD_TELEGRAM_BOT_TOKEN and PROD_TELEGRAM_WEBHOOK_SECRET, and the API/bot shared secret is PROD_API_SHARED_SECRET. The smoke test must read secrets from the environment or CI secrets and never hardcode them in tracked files. (source: docs/ci-cd/gcp-setup.md)
r5. The smoke test must not deploy anything. Deploys are owned by .github/workflows/deploy.yml (jobs test, infra, deploy, deploy-api, deploy-web), and the smoke test should run after them without altering infra. (source: docs/ci-cd/gcp-setup.md)
r6. Pulumi owns infra and `gcloud run deploy` owns the image and env vars. A smoke test must not touch either. (source: docs/ci-cd/gcp-setup.md)
r7. Dependency-cruiser rules and the no-dynamic-imports check run in the review-factory-gate job. New code must pass both, so no dynamic imports. (source: docs/ci-cd/gcp-setup.md)
r8. Record non-obvious, hard-won findings (infra gaps, environment gotchas) in docs/memories/, dated and terse, with file:line references, and add them to the index in README.md. (source: docs/memories/README.md)
r9. Shared pure logic lives in @post-anki/core (packages/core). Do not hand-roll a duplicate of an existing shared helper. (source: docs/architecture/agent-conventions.md)
