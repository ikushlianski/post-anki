# Plan: web sign-in by magic link

## Goal
Only an email already in `users` can sign in to https://postanki.ilya.online, by a one-time emailed link; every page, server function and server route refuses without a session.

## Docs checked (Better Auth 1.7.12 = npm `latest`, pin exactly `1.7.12`; magic-link source read in the published package)
- Magic link: https://better-auth.com/docs/plugins/magic-link (`sendMagicLink`, `expiresIn` seconds, `disableSignUp`, `storeToken: "hashed"`, built-in limit 5 per 60 s on sign-in and verify; token consumed atomically on first use).
- Drizzle adapter: https://better-auth.com/docs/adapters/drizzle (`provider: "pg"`, `usePlural: true`; schema via `npx auth@latest generate`, then our drizzle migration; no `migrate` for Drizzle).
- Rate limit: https://better-auth.com/docs/concepts/rate-limit (`storage: "database"`; client IP from `advanced.ipAddress.ipAddressHeaders`, default `x-forwarded-for` chains are not trusted).
- TanStack Start: https://better-auth.com/docs/integrations/tanstack (`/api/auth/$` catch-all route, `tanstackStartCookies()` plugin) and Resend: https://resend.com/docs/api-reference/emails/send-email (`POST https://api.resend.com/emails`, bearer key, needs a `User-Agent` header).
- Finding: `disableSignUp` only blocks at verify time; `/sign-in/magic-link` still stores a token and calls `sendMagicLink` for ANY email. The no-email-for-unknown rule therefore lives in our `sendMagicLink` callback.
- Finding: adapter 1.7.12 needs `drizzle-orm ^0.45.2` and drizzle-kit >=0.31.4; `apps/api` and `apps/bot` pin `^0.36.0` / `^0.28.0`. A bump is step 1.

## Approach (recommendation: option a, Better Auth in the API)
- Better Auth runs inside `apps/api` (new `apps/api/src/auth/`), mounted at `/api/auth/*` behind the existing `authorized()` shared-secret gate. The web server never opens a DB connection (`apps/web` has no `pg`/`DATABASE_URL`); option b would add one, a second migration owner and `DATABASE_URL` to the web service, breaking the rule that the API owns data.
- Browser talks only to the web origin. Web gets a thin proxy `routes/api.auth.$.ts` that forwards only `POST sign-in/magic-link`, `GET magic-link/verify`, `POST sign-out` (everything else 404) to the API with the shared secret, `redirect: manual`, forwarding cookie/origin/content-type and returning every `Set-Cookie` plus 302s untouched. Cookies are therefore host-only on the web origin. `tanstackStartCookies()` is not needed (option a).
- Better Auth config: `baseURL = BETTER_AUTH_URL` (the public web origin) so emailed links point at the web origin; `trustedOrigins=[that origin]`; `magicLink({ expiresIn: 600, disableSignUp: true, storeToken: "hashed", sendMagicLink })`; `session.expiresIn` 30 days; `rateLimit.storage: "database"`; client IP from a header the web proxy sets (`x-pa-client-ip` = right-most `x-forwarded-for`).
- `sendMagicLink`: look up `users` by email; unknown -> send nothing, wait ~700 ms (equalise timing), return normally, so both cases answer `{status:true}`. Known -> `POST https://api.resend.com/emails` by plain `fetch` (`RESEND_API_KEY`, `from` = `AUTH_EMAIL_FROM`). No `resend` package.
- Tables (generated by Better Auth, plural names): `users`, `sessions`, `accounts`, `verifications`, rate-limit table, added to `apps/api/src/db/schema.ts`; migration from `drizzle-kit generate`, applied by `db:migrate`, never push.
- Status for the web gate: new `POST /web-auth/checks` {cookie} -> {state: `unconfigured` | `signed_out` | `signed_in`}; `unconfigured` = no `RESEND_API_KEY` or zero users. Uses `auth.api.getSession`.
- Web global request middleware (`apps/web/src/start.ts`): `signed_in` pass; `unconfigured` -> dev pass, production 503; `signed_out` -> page GET redirects to `/login`, `/_serverFn/*`, `/api/*` and non-GET get 401. Open without session: `/login`, the proxy `/api/auth/*`, static assets. iOS and `api_tokens` untouched (they never use `/api/auth`).
- API env stays optional so the API always boots: if `RESEND_API_KEY` is set in production, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `AUTH_EMAIL_FROM` become required.

## Steps
Dispatch A (owns `apps/api/**`, `apps/bot/package.json`, `packages/shared/src/web-auth.ts`+`index.ts`, `package-lock.json`, `.github/workflows/deploy.yml`):
1. Bump `drizzle-orm ^0.45.2`, `drizzle-kit ^0.31.4` in api and bot; add `better-auth` `1.7.12` (exact) to api. Gate: `npm run db:generate` yields no new migration and `npx vitest run` is green.
2. `apps/api/src/shared/env.ts`: add `RESEND_API_KEY`, `AUTH_EMAIL_FROM`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` plus the production rule above.
3. `apps/api/src/auth/auth.ts` (lazy `getAuth()`), `auth-email.ts` (Resend fetch), `send-magic-link.ts` (known/unknown policy), `auth-status.ts` (`checkWebSession`).
4. Generate the schema with `npx auth@latest generate`, merge into `apps/api/src/db/schema.ts`, then `npm run db:generate` for the migration.
5. Wire `/api/auth/*` (via `better-auth/node` `toNodeHandler`, after `authorized()`) and `POST /web-auth/checks` in `api-server.ts`, `router.ts`, `router-table.ts`; zod types in `packages/shared/src/web-auth.ts`.
6. `apps/api/scripts/create-user.ts` + `auth/create-user.ts` + `db:create-user <email>` script: lower-cases, inserts `users` row with `emailVerified=true`, name "Owner", idempotent, prints no secrets.
7. `deploy.yml` API job: add `--set-env-vars` lines `RESEND_API_KEY=${{ secrets.PROD_RESEND_API_KEY }}`, `BETTER_AUTH_SECRET=${{ secrets.PROD_BETTER_AUTH_SECRET }}`, `BETTER_AUTH_URL=${{ vars.PROD_WEB_PUBLIC_URL || 'https://postanki.ilya.online' }}`, `AUTH_EMAIL_FROM=${{ vars.PROD_AUTH_EMAIL_FROM }}` next to `API_SHARED_SECRET` (~line 280). Web job needs no new env (it keeps `API_BASE_URL`, `API_SHARED_SECRET`, `NODE_ENV=production` from its Dockerfile).

Dispatch B (after A merges; owns `apps/web/**`):
8. `web-auth/web-auth.api.ts` (checks call through `request`), `web-auth.access.ts` (pure `decideWebAccess`), `web-auth.middleware.ts`, `src/start.ts` via `createStart`. Load skills `@tanstack/start-client-core#start-core/middleware` first (`npx @tanstack/intent@latest load <use>`).
9. `routes/api.auth.$.ts` proxy (allowlist, header/cookie handling, strip `host`/`content-encoding`/`content-length`, set `x-pa-client-ip`).
10. `routes/login.tsx`: email form posting JSON to `/api/auth/sign-in/magic-link` with `callbackURL: "/"`; always shows "Check your inbox" on success, a "try again later" message on 429; shows a short message for `?error=` from a bad/expired link.
11. Sign-out button in `nav/sidebar.tsx`: POST `/api/auth/sign-out` then navigate to `/login`.
12. Build with `npm run build -w @post-anki/web`, run `node .output/server/index.mjs`, and allow only the static prefixes actually observed for `/login` to render unauthenticated.

Sidebar sign-out test.

## Done when
- Production: any request without a valid session is refused (redirect or 401), including `/api/electric-shape`; unconfigured production serves 503; dev with no key or user stays open.
- An existing email receives a link valid ~10 min, usable once, starting a 30-day session; an unknown email gets the identical response and no email; no sign-up path exists.
- Sign-out ends the session; browser cookie is httpOnly, Secure (https), SameSite=Lax on the web origin.
- Migration generated by drizzle and applied by `db:migrate`; iOS tokens unchanged; `npx tsc --noEmit`, lint, `npx vitest run` and integration tests pass for api, web, shared, bot.

## Owner steps
1. `brew install resend/cli/resend`, `resend login`; create the free account, add the sending domain on ilya.online, add the DNS records Resend lists (owner approves), wait for "verified".
2. Create an API key; add GitHub secrets `PROD_RESEND_API_KEY`, `PROD_BETTER_AUTH_SECRET` (`openssl rand -base64 32`) and variable `PROD_AUTH_EMAIL_FROM` (e.g. `Post Anki <login@ilya.online>`).
3. Merge and deploy (migration runs in CI; web answers 503 until step 4).
4. `DATABASE_URL=<prod> npm run db:create-user -w @post-anki/api -- you@example.com`, then sign in at /login.

## Defaults chosen
- Option a (auth in API, web proxies): keeps the DB behind the API; costs one proxy route.
- Plain-fetch login form and no `better-auth` in web: no extra web dependency or bundle.
- Link expiry 600 s, hashed token storage: middle of 10-15 min, no raw tokens in DB.
- Sliding session (Better Auth default daily refresh) inside a 30-day lifetime.
- Timing padding on the unknown-email path rather than fire-and-forget: Cloud Run may throttle CPU after the response.
- Mail scanners that prefetch the GET link could burn it; accepted, owner requests another.
- `BETTER_AUTH_SECRET` added though not listed: Better Auth refuses default secrets in production.
