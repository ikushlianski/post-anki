## New actions + fixtures this run added

- `submitDecide({ page, decision, opinion })` — `features/decide/actions/submit-decide.action.ts` —
  navigates to `/decide` if needed, fills decision then opinion (opinion-first order matters), waits
  for the real `submitDecide` server-fn network response (`/_serverFn/<base64>` marker technique,
  reused from `lib/server-fn-response.ts`, first built for `check-my-writing-mode`), then reads back
  verdict/strengths/questions and each blind spot's `data-blind-spot-id`/`data-status`.
- `getDecideHistory({ page })` — `features/decide/actions/get-decide-history.action.ts` — reloads
  the page, reads `decide-history-item-<n>` in DOM order, returns each item's full text (the test
  asserts `.toContain()` against its own stamped decision string rather than parsing internal
  markup).
- `resolveDecideBlindSpot({ page, blindSpotId, resolution })` —
  `features/decide/actions/resolve-decide-blind-spot.action.ts` — finds the rendered blind-spot row
  by `data-blind-spot-id`, clicks its flag or dismiss button, waits for the real
  `resolveDecideBlindSpot` server-fn response, reads back `data-status`.
- `MOCK_DECIDE_JWT_VS_SERVER_SESSIONS` — new responder in
  `mock-openrouter/responses.ts`, matched on `schemaProps.includes('blindSpots')` (confirmed
  non-colliding with every other responder's schema keys in that file — no content-based branching
  needed, unlike `buildWritingCheckStub`, since this mock only ever needs to serve one deterministic
  decide-shaped response; S2 deliberately doesn't depend on the mock varying by request, per
  scenarios.md's own S2 UI-clicking notes).

Deviation from a literal reading of the plan: `playwright.md`'s S1 action-gap description mentions
reading a session id off the result card; no scenario actually consumes it (S3's setup reads blind
spot ids directly), so `submitDecide`'s result type does not include one — avoids requiring a
`data-session-id` testid that `playwright.md`'s own "Required data-testid attributes" list for S1
never names.

## Two real bugs found and fixed during the first green attempt

1. **`decide.tsx` used a `<form onSubmit>` + `type="submit"` button**, unlike `check-writing.tsx`'s
   already-proven pattern of a plain `type="button"` with `onClick` (no `<form>` at all). Suspected
   first as the cause of S1/S2/S3 all timing out on `submitDecide`'s `page.waitForResponse` despite
   the real POST completing with 200 (confirmed via a standalone repro script). Fixed by dropping the
   `<form>` wrapper — this did **not** turn out to be the actual cause (see bug 2), but is still the
   correct, established pattern for this codebase and was kept.
2. **The real cause: `lib/server-fn-response.ts`'s `decodeServerFnUrl` regex only captured standard
   base64 (`[A-Za-z0-9+/=]`), but TanStack Start encodes the `/_serverFn/<...>` descriptor as
   base64URL, which legitimately contains `-`/`_`.** decide-mode's specific descriptor string
   happened to produce a `-`/`_` in its output (`check-my-writing-mode`'s never did — coincidence,
   not a functional difference), so the regex silently truncated it, producing corrupted JSON that
   failed to parse, making `isServerFnResponse` always return `false` and every
   `page.waitForResponse` call time out at its full timeout — even though the exact right response
   had already arrived. Root-caused with a standalone repro script (a verbose predicate that logs
   every candidate response and decode attempt) rather than repeated 30-second full-suite re-runs.
   Fixed in the shared helper (widened the capture regex, normalize base64URL → base64 before
   decoding) — benefits every current and future action built on this helper, not a per-action
   workaround. Documented in `server-fn-response-base64url-bug.md` (new memory).
3. **`submitDecide`'s own text-extraction was reading the "·" bullet glyph** rendered before each
   list item and blind-spot description, corrupting the returned strings against the mock's exact
   text. Fixed by adding a dedicated `decide-blind-spot-description-<n>` testid (additive, not in
   `playwright.md`'s original list — added there too) and stripping the bullet from the plain
   strengths/questions list-item text.
