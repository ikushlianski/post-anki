## Real inconsistencies found between the plan and the actual codebase (not assumed — verified while writing these tests)

1. **`approve-sources` no longer reaches `status: 'ready'` directly.** A later structure-shaping-chat
   feature (`curriculum-structure.ts`) inserted a conversational-review gate: `approve-sources` now
   lands on `status: 'shaping_structure'`, and an additional `POST /curricula/:id/confirm-structure`
   call (no body needed — it accepts the initial AI-drafted snapshot as-is) is required to reach
   `ready`. spec.md's backend DoD sequence and the already-registered `study-technology-doc-url` e2e
   test both assumed the older, now-stale 3-step sequence. Both new e2e tests (S1, S3) were written
   against the verified, current 4-step sequence. Logged in
   `verification-repo/projects/post-anki/post-anki/docs/memories/confirm-structure-required-for-ready.md`.
   The pre-existing `study-technology-doc-url` test itself is currently broken by this same drift —
   NOT fixed here (out of this ticket's scope), flagged for a separate fast-follow.
2. **`mock-openrouter`'s `DOC_RESEARCH_STUB_PLAN` was missing a required (nullable) `tags` field**,
   breaking every docUrl-based curriculum in e2e with `Structured output validation failed:
   modules.N.tags: Required`. Fixed in this session (added `tags: null` to each module, mirroring
   `CURRICULUM_STUB_PLAN`'s existing shape) since it silently blocked every scenario in this plan —
   logged in
   `verification-repo/projects/post-anki/post-anki/docs/memories/doc-research-stub-plan-tags-field.md`.
3. **`TagPicker`'s tag-assignment mutations persist correctly but don't reliably reflect live in the
   SPA** without a reload (confirmed via direct `GET /curricula/:id` and a direct DB read — the data
   is correct, only the client-side re-render is stale after `router.invalidate()`). Worked around in
   the new `assignTagToModule`/`createTag` actions with a `page.reload()` after submit — this still
   asserts real, persisted state through the real UI (the SSR path), just not the live-update path.
   Not fixed here (out of this ticket's scope — `TagPicker` isn't part of this plan's change set).
   Logged in
   `verification-repo/projects/post-anki/post-anki/docs/memories/tag-picker-live-refresh-gap.md`.
